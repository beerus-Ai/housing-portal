# Housing Society Portal (Sahyadri Heights)

MBA assignment (BPA Using AI, Session 3 brief). Resident onboarding, work requests, notices, role-based dashboards, audit trail.

## Stack (and why)
Two stacks run side by side (ADR: `docs/architecture/adr-0001-java-react.md`, strangler migration). **Node is the default and the system of record until the Java backend reaches parity and cutover happens.**
- **Node (default, port 3000):** Node 22.5+ (built with 24), Express, `node:sqlite` (no native build step; swap for hosted Postgres in production), bcryptjs, express-session, multer.
- **Java (`backend/`, port 8080):** Spring Boot 3.3, Java 17+, Gradle wrapper, Spring Security session cookie, JPA, Flyway, H2 locally, PostgreSQL 16 in prod. Drop-in replacement for the Node API (same URLs, JSON, status codes, error strings).
- **React (`frontend/`, port 5173):** React 18, TypeScript, Vite, React Router, TanStack Query. Talks to either backend through the Vite proxy (`VITE_API_TARGET`).
- **Mobile (`mobile/`):** Capacitor Android wrapper around the PWA; `public/m/` stays until the React app replaces it.
- **Flutter (`flutter_app/`):** Flutter + Dart client on the same API (session cookie captured from `/api/login`); bottom nav by role, required items first (Home, Requests, Notices), extras under a More tab (amenities, dues, inventory, waste, gate pass); guards get a Gate desk tab (NFC card taps and registration via `nfc_manager`, same as `public/web-nfc.js`); `flutter test` (22). SDK on this machine: `E:\tools\flutter`. Product and technology architecture: `docs/architecture/product-and-technology-architecture.md`.
- Vanilla JS frontend in `public/` (no build step, strict CSP: no inline scripts). Navigation: a top bar holds each role's required items (Requirements Document / faculty whiteboard: `CORE` in `web.js`); the left sidebar holds only the extras (Administration, Modules, Help) and can be hidden (`hp.nav`). Animations are small Lottie JSON files in `public/anim/` played by `lottie-web` (`public/ui.js`). Fonts (Outfit, Plus Jakarta Sans) and Phosphor duotone icons are self-hosted in `public/vendor/`, so the CSP stays `'self'` only.
- Two clients on one API: the **web app** (`/`, desktop-first and responsive) and the **mobile app** (`/m/`, installable PWA with a bottom tab bar). Phones opening `/` are sent to `/m/` (add `?web` to stay). Design source: Claude Design handoff `Housing Portal.dc.html` (tokens in `public/css/tokens.css`, base components in `public/css/ds.css`).
- **AI module (in progress):** `ai.js` holds PII redaction, rule-based triage, optional LLM triage, notice drafter and weekly digest. AI only suggests; a committee member confirms assignments and sends notices. Never send names, phones, emails or flat numbers to a model.
- **WhatsApp intake (in progress):** `/api/whatsapp/webhook` (secret-checked) turns a message from a registered phone into a request and sends status replies; `/api/admin/whatsapp/simulate` exercises it without a provider. Env: `ANTHROPIC_API_KEY` (optional, enables LLM mode), `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`, `WHATSAPP_WEBHOOK_SECRET`, `SLA_HOURS` (default 48).
- **Telegram intake:** `/api/telegram/webhook` (same pipeline as WhatsApp). Env: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`. Request-vs-chatter gate can use a free n8n LLM: `CLASSIFY_WEBHOOK_URL`.
- **Email desk (`email-desk.js`):** new requests, review-queue messages, registrations and emergencies are POSTed to an n8n Gmail workflow (`ADMIN_EMAIL_WEBHOOK_URL`) when no admin has the dashboard open (emergencies always). Signed links open `/desk/<token>`; confirming replays the dashboard's own API route as the admin, so audit and notifications are the same. Env: `PUBLIC_URL` (else `RENDER_EXTERNAL_URL`), `EMAIL_ACTION_SECRET`. Node only so far.
- **Roles (faculty review, 2026-11-21, `roles.js`, `guides.js`, contract `docs/roles-api.md`):** `users.role` is resident | admin (committee) | guard | staff | it | shop (tuck shop owner) | laundry (laundry service); staff carry `users.department` cleaning | maintenance (strict: cleaning sees waste, maintenance sees inventory); committee accounts carry `users.position` member | head | sysadmin (empty = sysadmin). `governance` middleware (head or sysadmin) guards settings, access rules, accounts, guards and the Telegram webhook. Staff and IT have strict allow-lists in `auth` like guards. Costs over `approval_limit` need the head (sysadmin only when no head exists). Node only so far.
- **Society modules (faculty whiteboard, 2026-11-25, `modules.js`, `public/web-modules.js`, contract `docs/modules-api.md`):** amenity booking, maintenance dues with recorded payments (no online gateway yet), inventory with stock moves, waste schedule/log and missed-pickup requests; "Society services" row on the resident home and committee dashboard. Times are IST; `createApp({ clock })` fixes the clock in tests. Node and web only so far.
- **Resident services (2026-11-25, `services.js`, `public/web-services.js`, contract `docs/services-api.md`):** tuck shop (orders, stock), laundry (pickup booking, forward-only status), parcel desk (guards log, flat notified) and community events (RSVP). Pay on delivery; gateway planned. NFC gate cards (`nfc.js`, `public/web-nfc.js`, `docs/nfc-api.md`): guards register cards; taps check in/out and start or end staff shifts. Dashboards differ per role (`public/illus.js` scenes, `hero-<theme>` in `css/calm.css`; head, admin and member have different dashboards and top bars). Dashboards for every role are calm: greeting, one status line, a short "For you" list (`HP.hero`, `HP.notifier` in `common.js`, styles in `css/calm.css`).
- **Free hosting:** the SQLite file is wiped on sleep/redeploy. `SEED_PASSWORD` (6+ chars; the demo uses `test123`) seeds role accounts, vendors, shop items and laundry prices; `SEED_TELEGRAM_PHONE` / `SEED_TELEGRAM_ID` recreate the linked Telegram test resident (flat T-101).

## Run
- `npm start` -> http://localhost:3000. The database starts empty except for the committee admin (`admin@society.test`; set `ADMIN_EMAIL` / `ADMIN_PASSWORD`, required and 12+ characters in production). There is no demo data: register residents through the UI and enter only the minimum data when testing.
- `npm test` -> Node API tests (`node:test`, 140 incl. 53 cross-module `test/integration-*.test.js` including `test/modules.test.js`, `test/roles.test.js`, `test/ai.test.js`, `test/telegram.test.js`, `test/email-desk.test.js`). Every story ships with a test; testing leads sign off.
- Java: `cd backend && ./gradlew test` (JUnit, 81 tests); `./gradlew bootRun` for port 8080. Needs JDK 17+.
- React: `cd frontend && npm install && npm run dev`; `npm test` (Vitest, 67), `npm run lint`, `npm run build`.
- Mobile: see `mobile/README.md` (Capacitor, Android). Flutter: `cd flutter_app && flutter pub get && flutter test && flutter run` (see `flutter_app/README.md`).
- CI (`.github/workflows/ci.yml`) runs 6 jobs on every PR: Node, Java (H2), Java (PostgreSQL 16 + packaged boot), React, Docker image build, Flutter. Docker Compose (`docker-compose.yml`) has not been run end to end.
- Docs: `docs/` (index in `README.md`). Word copies in `docs/word/` are generated with `node E:\tools\md2docx\md2docx.js <docsRoot> <outDir> <md files...>` (run from that folder).
- Env: `PORT`, `SESSION_SECRET` (required in production), `DB_FILE`, `NODE_ENV=production` (secure cookies, trust proxy).

## Rules
- Never use real resident data in prompts, fixtures or tests. Synthetic only.
- Hash passwords, check role on every route (`auth`, `admin` middlewares), parameterised SQL only, escape all output in the UI (`esc`).
- Every state change writes to `audit` (who, what, when).
- Request lifecycle is forward-only: open → assigned → in_progress → closed; a vendor is required to progress; only closed requests can be rated, once. In the UI a closed request shows as "Resolved, awaiting rating" and becomes "Closed" when rated (the design's 5-step tracker).
- Visibility: residents see their own requests and any request from their own flat; committee sees all. Rating: the requester rates, but a family member never rates; the flat owner rates for them (`can_rate` is computed by the API, the UI never decides).
- Household: only an owner adds family/tenants (forced to their flat, created `pending`, committee approves). Tenant lease is set by the committee (`PUT /api/admin/users/:id/lease`) and read by the tenant.
- Build from JIRA stories one at a time; log key prompts/failures in `PROMPT_LOG.md`.
- Changes to the API contract must be made in Node, Java and `public/api.js` together; the Node tests are the behavioural spec for the ports.
- AI features: suggestions only, redact PII before any model call, rule-based fallback must work with no key, audit AI suggestions and human confirmations.
